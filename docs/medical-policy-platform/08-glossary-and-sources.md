# 8. Glossary and sources

## 8.1 Glossary

| Term | Meaning here |
|---|---|
| Medical policy / MNG | The plan's written coverage criteria for a service, device, test or medical-benefit drug; "Medical Necessity Guideline" is the unified Point32Health term |
| PA requirement / PA rule | The operational rule: whether a code, for a population, needs authorisation, by whom, through which channel, on what clock |
| LOB | Line of business: Commercial fully insured, Commercial self-insured (ASO), Medicare Advantage, SCO, One Care, MassHealth (Tufts Health Together), RITogether, Tufts Health Direct (Marketplace) |
| ePA | Electronic prior authorization: the CMS-0057-F Prior Authorization API implemented with the Da Vinci guides |
| CRD | Coverage Requirements Discovery: a CDS Hooks service that tells the EHR whether coverage and PA apply and what documentation is needed |
| DTR | Documentation Templates and Rules: FHIR questionnaires (standard or adaptive) with prepopulation logic in CQL |
| PAS | Prior Authorization Support: the FHIR Claim `$submit` and `$inquire` transactions mapped to X12 278 |
| PDex | Payer Data Exchange: the guide used for Patient Access, Provider Access and Payer-to-Payer APIs, including the Prior Authorization EOB profile |
| CQL / ELM | Clinical Quality Language and its compiled form; used for prepopulation and rule logic |
| SDC | Structured Data Capture: the base FHIR questionnaire profile DTR builds on |
| NCD / LCD / Article | Medicare National and Local Coverage Determinations and billing-and-coding Articles, published in the CMS Medicare Coverage Database (MCD) |
| InterQual / MCG | Licensed clinical criteria products (Optum and Hearst) |
| Delegated vendor | A UM organisation that manages authorisation for a category of services (Carelon, Evolent, eviCore, OncoHealth, EyeMed) |
| MHK | The UM and appeals platform (MedHOK CareProminence) |
| Onyx | The ePA platform vendor (OnyxOS / OnyxEPA, SAFHIR lineage) |
| NQTL | Non-quantitative treatment limitation, the parity concept covering PA, concurrent review, step therapy and medical-necessity criteria |
| IRR | Inter-rater reliability, the NCQA-required annual consistency test of reviewers |
| MoSCoW | Must, Should, Could, Won't prioritisation |

## 8.2 How the research was done and its limits

Five parallel research streams were run on 20 September 2026: the Itiliti Health profile, the competitive landscape, the regulatory inventory, Point32Health's current public state, and the standards content model. Around 200 web searches were executed. The research environment's network policy blocked direct page fetches of vendor, government, HL7 and news sites, so findings rest on search-engine excerpts of those pages, and the Da Vinci guide content was read from the HL7 GitHub source repositories, which were reachable. Every finding carries a confidence tag in its section. Nothing was invented: where a customer, number, statute section or product name could not be confirmed it is marked unverified. The prior Point32Health ePA documents in this repository's artefact history (ePA Workbench Internals, PAS Submit Conformance Review, ePA Interop Watch of 8 September 2026) supplied the organisational context.
